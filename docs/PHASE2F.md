# שלב 2ו — מוכנות לפרודקשן: התקנה, גיבויים מוצפנים, שמירת מידע וניטור

> **סטטוס: הושלם ✅** · השלב האחרון של [`PHASE2.md`](PHASE2.md).

## מטרה
שבעל עסק עם שרת Ubuntu ריק יעלה את כל המערכת בפקודה אחת, ויקבל:
- HTTPS;
- גיבוי יומי מוצפן ששוחזר בהצלחה בבדיקה;
- מחיקה אוטומטית של מידע שאין צורך לשמור;
- פקודת בדיקת מצב;
- Checklist ומסמכים משפטיים מעודכנים לגרסה עם שרת.

## 1. התקנה בפקודה אחת: `scripts/deploy-server.sh`
```bash
ssh root@server 'curl -fsSL https://raw.githubusercontent.com/diamondrubinny/menuai/main/scripts/deploy-server.sh | DOMAIN=menu.example.com EMAIL=you@example.com OWNER_EMAIL=you@example.com bash'
```

**מה הסקריפט עושה:**
1. מתקין Docker (מאגרי Ubuntu: `docker.io` + `docker-compose-v2`), nginx, certbot ו־age.
2. מוריד את הקוד ובונה את העורך (`dist/`).
3. יוצר `.env`:
   - סיסמת מסד נתונים אקראית (`openssl rand`).
   - הרשאות 600.
   - קובץ קיים **לא נדרס**, כך שהרצה חוזרת = עדכון.
4. מריץ `docker compose up -d --build --wait`.
5. כותב אתר nginx (ראו פירוט מתחת).
6. מפעיל HTTPS ו־HSTS (Let's Encrypt) כשמוגדר `EMAIL`.
7. מגדיר רוטציית לוגים ל־nginx: 14 יום, ובפורמט הלוג כתובת ה־IP מקוצרת.
8. מתקין גיבוי יומי (systemd timer) כשמוגדר `BACKUP_AGE_RECIPIENT`.
9. יוצר את הבעלים הראשון ומדפיס קישור כניסה (`OWNER_EMAIL`).

**אתר nginx:**
- מגיש את `dist/`.
- מעביר לשרת את `/api/`, `/m/` ו־`/media/`.
- כותרות אבטחה **רק** על העורך הסטטי. העמודים המפורסמים מקבלים את ה־CSP של השרת בלבד: שתי מדיניות CSP נאכפות יחד ושוברות את הסקריפט של התפריט.

| משתנה | ברירת מחדל | |
|---|---|---|
| `DOMAIN` | — (חובה) | הדומיין של האתר |
| `EMAIL` | — | מפעיל HTTPS (Let's Encrypt). בלי HTTPS ההתקנה נעצרת אחרי שלב nginx, כי השרת דורש `https://` בפרודקשן |
| `OWNER_EMAIL` | — | יוצר בעלים ראשון |
| `BACKUP_AGE_RECIPIENT` | — | מפתח ציבורי של age (`age1…`). המפתח הפרטי **לא נשמר בשרת** |
| `BRANCH`, `REPO`, `APP_DIR` | `main`, GitHub, `/opt/menuai` | |

## 2. גיבויים מוצפנים: `scripts/backup.sh` / `scripts/restore.sh`
- **מה נכלל:**
  - `pg_dump` של המסד;
  - ה־volumes של התמונות (`uploads/public` בלבד, לא ההסגר);
  - התפריטים המפורסמים.
- **הצפנה:** הכל נכתב לקובץ `tar` אחד שמוצפן ב־**age** למפתח ציבורי. בשרת אין דרך לפענח את הגיבוי, כך שגניבת השרת או הגיבויים לא חושפת מידע.
- **שמירה:** `BACKUP_DIR` (ברירת מחדל `/var/backups/menuai`), הרשאות 600, ומחיקה אחרי `BACKUP_KEEP_DAYS` (ברירת מחדל 14). מומלץ להעתיק לאחסון חיצוני (rsync/S3).
- **שחזור:** `restore.sh <file.age> <identity-file>`:
  - דורש אישור מפורש (`--yes`);
  - עוצר את השרת ומשחזר מסד, תמונות ותפריטים;
  - מפעיל מחדש ובודק תקינות (`health`).
- **נבדק בפועל:** גיבוי ← מחיקת נתונים ← שחזור ← השוואת תוכן.

## 3. מדיניות שמירה (Retention), נאכפת בקוד
רצה פעם ביממה בשרת, ואפשר גם ידנית: `cli.mjs retention`.

| מידע | נמחק אחרי | מקור הדרישה |
|---|---|---|
| קישורי כניסה (נוצלו/פגו) | 24 שעות | PHASE2 §9 |
| סשנים שפג תוקפם | מיד אחרי התפוגה | צמצום מידע |
| יומן ביקורת | 12 חודשים | PHASE2 §9 |
| שורות העלאה שנדחו (בלי קובץ) | 12 חודשים | ביקורת אבטחה |
| תמונות יתומות | 24 שעות (2ה) | צמצום מידע |

## 4. ניטור ובדיקת מצב
- `cli.mjs status`: מסד נתונים, ClamAV (PING), מקום פנוי בדיסק, מספר תפריטים, משתמשים ותמונות, ומועד הגיבוי האחרון. מחזיר קוד יציאה ≠ 0 אם משהו לא תקין, ולכן מתאים ל־cron או לכלי ניטור.
- `/api/health` נשאר ציבורי ומינימלי. מומלץ לחבר אותו לכלי זמינות חיצוני (למשל Uptime Kuma בהתקנה עצמית).
- **אירועי אבטחה ביומן:** כניסות, הזמנות, שינוי הרשאות, פרסום, מחיקה, קבצים נגועים ופעולות CLI.

## 5. שרשרת אספקה
- ב־CI:
  - SBOM (CycloneDX, `npm sbom`) כ־artifact בכל ריצה;
  - `npm audit` לתלויות בזמן ריצה;
  - בדיקת סקריפטי shell עם **shellcheck**.

## 6. מסמכים
- `PRODUCTION_CHECKLIST.md` נכתב מחדש לגרסה עם שרת. הוא כולל:
  - טבלת מידע אישי ורשימת עוגיות;
  - בדיקות הרשאות, העלאות ואנטי־וירוס;
  - גיבוי ושחזור, סודות ותלויות;
  - נגישות ו־RTL;
  - ונושאים שדורשים אישור של עורך דין, ממונה פרטיות, יועץ נגישות או בודק חדירות.
- טיוטות מעודכנות: מדיניות עוגיות (עוגיית סשן חיונית אחת), תנאי שימוש (גרסת שרת), **מדיניות שמירה ומחיקה** (חדש).
- כל המסמכים מסומנים כטיוטות שדורשות בדיקה משפטית.
