# שלב 2ד — פרסום בלחיצה לכתובת קבועה, QR, היסטוריה ושחזור

> **סטטוס: הושלם ✅** · חלק משלב 2 ([`PHASE2.md`](PHASE2.md)) · ממשיך את [`PHASE2C.md`](PHASE2C.md).

## מטרה
בעל העסק לוחץ „פרסום” והתפריט מתעדכן מיד באותה כתובת, למשל `https://menu.example.com/m/lumiere`. קוד ה־QR שעל השולחנות לא משתנה לעולם. כל פרסום נשמר כגרסה, ואפשר לשחזר גרסה קודמת.

## החלטות
| נושא | החלטה | למה |
|---|---|---|
| מי מייצר את ה־HTML | **השרת**, מתוך הטיוטה השמורה במסד, עם אותו מנוע ייצוא (`src/core/exportHtml.ts`) | אם הדפדפן היה מעלה HTML מוכן, כל עורך יכול היה לשתול סקריפט בדומיין של העסק. כך השרת מפרסם רק תפריט שעבר ולידציה ונוצר מקוד מוכר |
| איפה הקובץ | `PUBLISH_DIR/<slug>.html`, כתיבה אטומית (קובץ זמני + rename) | אין מצב ביניים של קובץ חצי כתוב |
| מי מגיש את `/m/:slug` | השרת (Fastify) קורא את הקובץ הסטטי. nginx מעביר את `/m/` אליו | התקנה פשוטה: Volume אחד, בלי הרשאות קבצים משותפות בין קונטיינר ל־host. קריאת קובץ קטן מהדיסק, בלי מסד נתונים בדרך של האורח |
| כתובת קבועה | `publications.public_slug` נקבע בפרסום הראשון ולא משתנה | QR מודפס נשאר תקף |
| עקביות | פרסום דורש `If-Match` של גרסת הטיוטה | מתפרסם בדיוק מה שהמשתמש רואה; העורך שולח קודם שינויים שממתינים |
| היסטוריה | כל פרסום = שורה ב־`menu_versions`; נשמרות 50 האחרונות לכל תפריט (הגרסה המפורסמת לא נמחקת) | תמונות מוטמעות הופכות כל גרסה לכבדה; 50 מספיקות לשחזור |
| שחזור | `restore` מעתיק גרסה **לטיוטה** (לא מפרסם אוטומטית) | אפשר לבדוק לפני פרסום מחדש. מכשירים אחרים מקבלים את הטיוטה המשוחזרת דרך הסנכרון |

## API
| Method | Path | תפקיד | הערות |
|---|---|---|---|
| POST | `/api/menus/:id/publish` | editor | `If-Match` חובה; `{ note? }` → גרסה חדשה + קובץ HTML. 409 אם הטיוטה השתנתה |
| GET | `/api/menus/:id/versions` | viewer | `{ publication, versions[] }` בלי תוכן הגרסאות |
| POST | `/api/menus/:id/restore/:versionId` | owner | מעתיק לטיוטה, `draft_version + 1`; מחזיר את הטיוטה |
| POST | `/api/menus/:id/unpublish` | owner | מוחק את הקובץ ואת הפרסום; הכתובת נשמרת לפרסום הבא |
| GET | `/m/:slug` | **ציבורי** | HTML סטטי; CSP קפדני בכותרת (hash של הסקריפט), `connect-src` חסום, בלי עוגיות; 404 ידידותי |

מחיקת תפריט מוחקת גם את הקובץ המפורסם.

## אבטחה
- `/m/:slug`: הנתיב עובר regex לפני כל גישה לדיסק, כך שאי אפשר לצאת מהתיקייה (path traversal).
- כותרות האבטחה בעמוד המפורסם:
  - `default-src 'none'`, כך שהעמוד לא יכול לשלוח בקשות (fetch) ל־API של אותו דומיין.
  - `script-src` מותר רק לפי ה־hash של סקריפט התפריט.
  - `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy: no-referrer`.
- עוגיית הסשן מוגבלת ל־`Path=/api` וגם HttpOnly, כך שהעמוד המפורסם לא רואה אותה.
- Rate limit לעמודים הציבוריים: 1200 לדקה לכל IP. כך גם הרבה אורחים מאותה רשת Wi‑Fi לא ייחסמו.
- יומן ביקורת: `menu.publish`, `menu.unpublish`, `menu.restore`.

## פרטיות
אורחים: השרת לא שומר עליהם שום מידע ולא שולח להם עוגיות. ב־Fastify אין לוג גישה לעמודים הציבוריים: לוג הבקשות מסונן עבור `/m/`. נשארים רק לוגי nginx, לפי ההגדרה של בעל השרת (מומלץ IP מקוצר ושמירה ל־14 יום, ראו PHASE2 §9).

## צד לקוח
- מקטע „ענן”:
  - כפתור **פרסום** והכתובת הציבורית עם „העתקה” ו„פתיחה”.
  - קוד QR שממולא אוטומטית בכתובת הקבועה.
  - **היסטוריית גרסאות** עם „שחזור” (בעלים).
  - „ביטול פרסום” (בעלים).
- לפני פרסום, העורך שולח שינויים שעוד ממתינים. אם אין חיבור או שיש התנגשות, מוצגת הודעה ולא מתפרסם תוכן ישן.

## בנייה
- השרת נארז עם esbuild דרך `scripts/build-server.mjs`:
  - ‎`?raw` → טקסט.
  - ‎`?url` של גופנים → קבצים ב־`dist-server/fonts/`.
- `npm run server:dev` משתמש באותו סקריפט במצב watch.
